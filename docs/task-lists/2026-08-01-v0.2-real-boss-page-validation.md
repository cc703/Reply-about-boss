# v0.2 Real BOSS Page Validation Task List

## Objective

Validate the v0.1 listener on a real BOSS Zhipin web chat page and decide whether the message detection rules need repair before adding any new feature.

## Work Content

- Load the unpacked extension from `extension/`.
- Open a real BOSS web chat page while logged in.
- Check whether the right-side `BOSS Chat Listener` panel appears.
- Confirm the panel identifies the latest HR-side text message.
- Confirm it does not identify:
  - the user's own right-side message,
  - time separators,
  - job cards,
  - competition/analysis cards,
  - read receipts,
  - extension panel text.
- If recognition fails, capture only anonymized DOM/class evidence and update detection rules.
- Do not add AI, DeepSeek, copy button, input fill, or auto-send behavior in this step.

## Work Prompt

Use this prompt when handing the task to a future session or agent:

```text
Read AGENTS.md and docs/task-lists/2026-08-01-v0.2-real-boss-page-validation.md. Validate the existing BOSS Chat Listener extension on a real BOSS web chat page. Keep the scope to listener validation and detection-rule repair only. Do not add AI, DeepSeek, copy, fill-input, or send features. If live validation cannot be automated, guide the user through loading the extension and collect only anonymized observations. After finishing, create the next task-list Markdown file under docs/task-lists/.
```

## Required Skills

- `build-web-apps:frontend-testing-debugging`: use if browser rendering or injected panel behavior needs debugging.
- `superpowers:systematic-debugging`: use if detection fails or produces inconsistent results.
- `superpowers:verification-before-completion`: use before claiming validation or repairs are complete.

## Useful MCP / Tools

- `tool_search`: optional, discover browser/control tools if live validation needs more automation.
- `mcp__omx_trace`: optional, inspect agent flow only if orchestration/debug history matters.
- `mcp__omx_code_intel`: optional, check local diagnostic backend availability.
- Shell: required for `npm.cmd test`, `npm.cmd run check`, and file inspection.
- Chrome/Edge extension page: required manual surface unless a browser-control tool is available.

## Recommended Agent Modules

- `explore`: map existing files and detection logic if starting from a fresh session.
- `debugger`: isolate bad selector/scoring behavior if the wrong message is detected.
- `test-engineer`: add or revise fixture cases based on anonymized live-page structure.
- `executor`: make scoped detection-rule fixes.
- `verifier`: review final evidence before moving to v0.3.

Do not use `worker` unless an active team/swarm runtime explicitly requires it.

## Stop Condition

- validates the current listener behavior, or
- exposes a detection problem that has a fixture, fix, and passing tests.

Do not expand into reply generation or copy/fill controls during this step.
