# v0.9 Live Reply Quality QA Task List

## Objective

Validate v0.8 reply quality on real BOSS conversations across common recruiter intents, confirming that drafts focus on the latest HR message and do not invent candidate facts.

## Work Content

- Reload the unpacked extension so version `0.8.0` is active.
- Verify the current backend is healthy and the Key status is configured without exposing the Key.
- Test manual draft generation against several existing real conversations.
- Check latest-message focus, factual grounding, non-repetition, tone, and one-question limit.
- Record only anonymized failure patterns and add regression tests before any code fix.

## Work Prompt

Use this prompt when handing the task to a future session or agent:

```text
Read AGENTS.md, docs/superpowers/specs/2026-08-16-reply-quality-context-design.md, docs/superpowers/plans/2026-08-16-reply-quality-context-plan.md, docs/validation/2026-08-16-reply-quality-context-validation.md, and docs/task-lists/2026-08-16-v0.9-live-reply-quality-qa.md. Verify backend health without printing the saved API Key, reload extension version 0.8.0, refresh the BOSS page, and manually generate drafts across general greeting, technical question, recruiter follow-up, job-detail, and interview-scheduling conversations. Confirm each draft answers the latest HR intent, uses only facts present in candidate-authored context, does not repeat answered questions, and remains manual-copy only. For failures, record anonymized wording, write a failing regression test, then implement the smallest fix. Do not add auto-fill, auto-send, cookie handling, login automation, or persistent chat storage.
```

## Verification Checklist

- [ ] At least five intent categories are checked on real conversations.
- [ ] Latest-message focus is correct in every passing case.
- [ ] Candidate facts are grounded in candidate-authored records.
- [ ] Unsafe or empty output produces a controlled error rather than an untrusted draft.
- [ ] The retry remains capped at one additional DeepSeek request.
- [ ] API Key and private conversation data do not appear in logs, source, fixtures, or reports.
- [ ] `npm.cmd test` and backend `unittest` pass after any fix.

## Stop Condition

Stop when all five intent categories pass with grounded, relevant, manual-only drafts and the anonymized validation report is complete. Stop and report a blocker if fixing a failure would require platform bypass, cookie access, automatic sending, or storing private chat history.
