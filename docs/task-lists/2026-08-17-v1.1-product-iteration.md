# v1.1 Product Iteration Task List

## Objective

Improve reply-draft usefulness and live-page resilience without weakening the human-in-the-loop or credential privacy boundaries.

## Work Content

- Review anonymized live cases for recruiter questions, continued discussion, rejection, and natural closing.
- Improve transcript extraction only when a reproducible fixture demonstrates a classification error.
- Improve draft grounding and tone choices without adding automatic fill or send behavior.
- Add focused fixtures and regression tests for every accepted behavior change.
- Recheck the extension on a real BOSS page before publishing the iteration.

## Work Prompt

```text
Read AGENTS.md, docs/references/open-source-lessons.md, the latest v1.0 validation record, and this task list. Inspect the current extension and backend before editing. Use anonymized fixtures to reproduce one bounded v1.1 improvement, keep all communication human-reviewed, keep the API Key in Windows Credential Manager, add regression tests first, then implement and verify the change. Do not add auto-fill, auto-send, cookie handling, login automation, or persistent chat storage.
```

## Open Source References To Consult

- `docs/references/open-source-lessons.md`
- `iiwish/chatboss` for lightweight job-seeking assistant UX.
- Official Chrome Manifest V3 extension documentation for supported browser behavior.

## Required Skills

- `superpowers:brainstorming`
- `superpowers:systematic-debugging` when a live extraction issue is reproduced.
- `build-web-apps:frontend-testing-debugging` for rendered panel behavior.
- `superpowers:test-driven-development`
- `superpowers:verification-before-completion`

## Useful MCP / Tools

- Git and shell: required for tests and release inspection.
- Browser control: optional for the logged-in local Chrome validation.
- Web access: optional for current official extension documentation.

## Recommended Agent Modules

- `explore`: map the current implementation and fixtures.
- `test-engineer`: define a minimal regression fixture.
- `executor`: implement the bounded change.
- `verifier`: inspect tests, privacy boundaries, and live-validation evidence.

## Expected File Changes

- Create or modify only the fixture, implementation, tests, and validation/task-list files required by the accepted v1.1 issue.
- Do not modify credential storage to expose a Key.
- Do not add automatic message filling or sending.

## Execution Checklist

- [ ] Select one reproducible v1.1 issue.
- [ ] Add an anonymized fixture and failing regression test.
- [ ] Implement the smallest compatible fix.
- [ ] Verify extension and backend behavior.
- [ ] Record live-page evidence without private chat content.

## Verification Checklist

- [ ] `npm.cmd test` passes.
- [ ] `npm.cmd run check` passes.
- [ ] Backend tests and compile check pass.
- [ ] Privacy scan has no new findings.
- [ ] Manual human-review and no-send boundaries remain intact.

## Stop Condition

Stop after one bounded issue is fixed and verified. Defer unrelated improvements to a new task list.
