# v0.2b Resume Action Detection Fix

## Scope

Fix a live-page detection issue where the listener selected a resume action label instead of the latest HR-side chat bubble.

## Anonymized Symptom

On a real BOSS chat page:

- The extension panel appeared.
- The panel status was `识别不确定`.
- The selected text was a short resume action label.
- A real HR-side message bubble appeared earlier in the message stream.

No raw screenshot, company name, job title, contact details, or chat screenshot is stored in this repository.

## Root Cause

The extractor accepted low-confidence action text as a candidate and selected the latest matched candidate by DOM order. On the live page, the resume action label appeared later in the DOM than the real HR-side message, so it replaced the actual chat bubble in the panel.

## Changes

- Added resume-action labels such as `发简历`, `发送简历`, `投递简历`, `立即投递`, and related terms to the exact ignore list.
- Changed selection to prefer high-confidence HR candidates first. If no high-confidence candidates exist, it still falls back to the latest matched uncertain candidate.
- Added a regression test for the resume-action-over-chat-bubble case.
- Added an anonymized fixture: `extension/test-fixtures/boss-chat-resume-action-sample.html`.

## Verification

Commands run:

```powershell

```

Results:

- Chrome headless fixture check showed the panel with `识别成功` and the anonymized HR-side message, while the page still contained the later resume action label.
