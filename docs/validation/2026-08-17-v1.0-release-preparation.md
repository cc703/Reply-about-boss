## Security Boundary Review

- The extension content script is limited to `zhipin.com` pages.
- The extension only has host permissions for the localhost backend.
- The backend startup command binds to `127.0.0.1:8765`.
- API Key values are sent only to the localhost backend in a request header during a user-triggered save, then stored by Windows Credential Manager.
- The backend never returns the Key, and the extension does not save it in extension storage or page DOM.
- Draft requests only occur after a manual click and transmit cleaned HR/self transcript records, tone, and reply purpose to the local backend. The local backend then calls DeepSeek.
- No BOSS input filling, automatic sending, login automation, cookie access, platform API interception, batch outreach, or persistent chat storage is included.

## Residual Risk

The local backend allows requests from Chrome extension origins so an unpacked extension can communicate with its dynamic extension ID. This does not expose the stored Key, but another locally installed extension with localhost access could attempt to alter or clear the local credential. Treat the browser extension set as part of the local trust boundary; do not install untrusted extensions on the same profile.
